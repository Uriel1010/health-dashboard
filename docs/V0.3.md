# Version 0.3 — Nutrition trends and widget choices

## Product scope

The main additions are account-wide nutrition statistics and a home-screen widget gallery. Today's progress and meal workflows stay available. The app has five navigation destinations: Today, Food, Trends, Health and Settings. The existing wide progress-bar widget and compact rings widget remain available alongside a configurable average widget. Material surfaces use softer, consistent corners.

## Shared statistics contract

`GET /api/v1/nutrition/statistics` uses the existing authenticated account and its nutrition reset hour in the server timezone. It queries only that account's active, non-deleted meals. No database migration is required.

- Let D be the current nutrition date. The 7, 14 and 30 day windows are [D−N, D−1], inclusive. Today is never included. The month option means 30 days, not the previous calendar month.
- Meals are grouped by the same nutrition-day boundary used by Today. Multiple meals are summed before averaging.
- Missing registration is unknown, not zero intake. A recorded zero is a real observation and counts in the denominator.
- Each nutrient has its own coverage count. If any meal is missing that nutrient on a day, that day's nutrient total is unknown and excluded. This particularly affects optional fiber values.
- Average = sum of known daily totals / count of those known daily totals. No observations returns null, displayed as an em dash. Values are rounded to two decimals by the API and one decimal for display.
- Coverage is visible because a registered day can still be partial; these statistics do not establish that logging is complete.
- Goal comparisons refer to current goals. They do not imply historical targets.

The response supplies date boundaries, timezone, reset hour, all 30 daily points, three average windows and per-nutrient coverage. Both clients consume this one contract rather than recomputing different averages.

## App and dashboard

Trends offers 7/14/30 selectors, all five nutrient averages, explicit dates and coverage, a selectable daily bar chart, and a readable daily values list/table. Missing points are distinct from recorded zeros. The app provides loading, retry and signed-out feedback and an account-scoped saved cache. A session or server change cannot reveal the previous cache.

## Widgets

Settings → Home screen widgets offers wide progress bars, compact rings and nutrition averages. Each average widget has its own period and nutrient settings and can be reconfigured on supporting launchers. Its saved date range, coverage and exclusion of today are shown. Tapping it opens Trends. The user chooses the period and nutrient before pin confirmation. A unique success callback saves those choices to the allocated widget ID because Android's pin-widget API skips the normal configuration activity. Widgets added through the launcher use the normal configuration activity.

Background nutrition sync refreshes the statistics cache when server-meal sync and widget refresh are enabled. Trends refresh also updates widgets. Offline widgets retain explicitly dated saved results. No user account data or credentials belong in public screenshots or fixtures.

## Verification

Backend tests cover window boundaries, exclusion of today, reset-hour grouping, multiple meals per day, sparse and empty history, genuine zero values, and incomplete fiber. Dashboard tests use synthetic data on desktop and mobile to exercise all periods and nutrient selection and check horizontal overflow. Android debug/release builds and unit tests verify compilation and existing behavior. Launcher appearance and pin confirmation still depend on the device's launcher.
